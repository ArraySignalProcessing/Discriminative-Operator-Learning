# Task-Driven Discriminative Operator Learning for MUSIC-Based DOA Estimation

This repository contains the source code for training and evaluating a task-driven discriminative operator network (DMN) for MUSIC-based direction-of-arrival (DOA) estimation.

All training data, test data, intermediate results, and figures are generated by the included Python and MATLAB programs. No experimental dataset is required from an external source.

## Relationship to the manuscript

The current manuscript uses six experiment groups:

- **B1**: noise-subspace projector deviation under finite snapshots and low SNR.
- **B2**: spectral-gap narrowing and projector deviation under source correlation.
- **B3**: spatial-response comparison between the sample noise-subspace projector and the learned operator.
- **B4**: ablation of the operator-construction criteria.
- **C1**: resolution of closely spaced sources.
- **C2**: robustness to correlated and fully coherent sources.

The repository also retains additional experiments that are not used for the main figures or quantitative claims of the current manuscript:

- **B5**: consistency between grid and Root-MUSIC-type inference backends.
- **B6**: exploratory source-count experiments for `K=1,2,3`.
- **C3**: array-model mismatch.
- **C4**: SNR sweep.
- **C5**: snapshot-count sweep.
- **Root-Ours**: an alternative Root-MUSIC-type backend for the learned operator.

See [docs/PAPER_CODE_MAP.md](docs/PAPER_CODE_MAP.md) and [docs/EXTENDED_EXPERIMENTS.md](docs/EXTENDED_EXPERIMENTS.md) for details.

The source-level classification is listed in [docs/CODE_INVENTORY.md](docs/CODE_INVENTORY.md).


- PyTorch 2.x
- NumPy
- h5py

## Main training workflow

The proposed method is trained from population covariance matrices generated on the DOA grid described in the manuscript.

```bash
cd python_Ours
python Ours_Generate_allpairs.py --out Ours_train.h5
python Ours_train.py --data Ours_train.h5 --output ours_model.pth
```

MLC baseline:

```bash
cd python_CNN
python CNN_Generate_allpairs.py --out CNN_train.h5
python CNN_train.py --data CNN_train.h5 --output cnn_model.pth
```

SubspaceNet baseline:

```bash
cd python_SubspaceNet
python SubspaceNet_Generate_train.py --out Subspace_train_rho.h5
python train_SubspaceNet.py --data Subspace_train_rho.h5 --output subspace_model.pth
```

These commands generate large local files. Generated `.h5`, `.mat`, `.pth`, `.npz`, and figure files are intentionally excluded from the source repository.

## Reproducing the experiments

The experiment pipeline is:

```text
generate training data
        -> train learning-based methods
        -> generate common finite-snapshot test observations
        -> evaluate MATLAB and learning-based methods
        -> aggregate RMSE/PoR or operator responses
        -> plot the figures
```

The complete script-by-script sequence for B1-B4 and C1-C2 is documented in [docs/REPRODUCTION.md](docs/REPRODUCTION.md). Generated files and their producers/consumers are documented in [docs/GENERATED_FILES.md](docs/GENERATED_FILES.md).

## Method naming

The source directory `python_CNN` retains its historical name. The corresponding grid-based multi-label classifier is called **MLC** in the manuscript. `python_Ours` implements the proposed DMN. Root-Ours uses the learned operator with a Root-MUSIC-type backend and is not the default backend in the current manuscript figures.

## Optional CVX dependency

CVX is needed only when the optional l1-SVD branches are enabled. It is not bundled with this repository. The main manuscript workflow keeps those optional branches disabled. See [docs/THIRD_PARTY.md](docs/THIRD_PARTY.md).

## Reproducibility notes

- All simulated observations are generated locally.
- Training and test data are distinct.
- Training DOAs lie on the grid; performance-test DOAs are off-grid.
- Random seeds are set in the individual scripts.
- At least 1,000 Monte Carlo trials are used per operating point in the manuscript performance experiments.
- Numerical results may vary slightly across hardware, MATLAB releases, PyTorch versions, and CUDA implementations.
